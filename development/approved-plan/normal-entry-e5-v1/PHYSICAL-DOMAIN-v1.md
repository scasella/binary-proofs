# Physical normal-entry interpretation, E5 v1

This document lists the physical conditions used to interpret the new checked RF=TF=0 theorem. It does not introduce a logical `valid_state` predicate or assume the program's functional result. The RF housekeeping correspondence claim is one specific projection of normal scalar execution, not complete hardware refinement.

The pinned Intel 253669-078US volume 3B §18.3.1.1 clears RF at instruction start after initial checks. E5's clear-after mathematical overlay is equal to the original model only when RF stays zero; start and end placement of a write of the already-zero bit then have equal states. E5 does not cover RF=1, IRET/task switches, fault priority, or debug-resume behavior. §18.3.1.4's TF single-step path is excluded by TF=0. DR7 L0/G0 through L3/G3 (bits 0–7) are all clear, excluding ordinary instruction/data breakpoints. General Detect is irrelevant for the qualified instruction set because it contains no MOV to/from a debug register. No INT1 or task-switch instruction is reached. Any debugger modification or delivered interrupt/NMI/machine-check event is outside the sequential call.

Long mode, CPL=3, ordinary Linux user CS/SS/DS/ES selector interpretation, flat CS/SS addressing and disabled CET are environmental assumptions. The declared CPU/OS feature profile licenses every qualified encoding, including the AMD-primary REP RET interpretation already listed in E3. The model's canonical48 memory addresses are interpreted on a processor configured with 48-bit canonical addressing; the experiment does not silently claim LA57 coverage. Page/fetch permissions are those in the original image and explicit region predicates; no device memory is admitted. AC is zero by the old Pre, so the alignment-check mechanism does not introduce a trap for the admitted unaligned accesses. The original nonwrapping and canonical span/return/GOT premises bound the normal memory/control accesses. They do not model page-table walks, physical memory errors or OS fault handlers.

A physical user RFLAGS image must satisfy the architectural fixed/reserved-bit rules: bit 1 is one; bits 3, 5 and 15 are zero; reserved high bits 22–63 are zero. The usual Linux user-entry image additionally has IOPL bits 12–13 = 0, NT bit 14 = 0, VM bit 17 = 0, and VIF/VIP bits 19–20 = 0; AC bit 18 = 0 and DF bit 10 = 0 are already original contract requirements. ID bit 21 and IF bit 9 are not newly assigned by these routines. RF bit 16 and TF bit 8 are zero in E5. The outside-status-bit lemma proves stability of all of these modeled bits; the six mutable arithmetic-status bits are 0,2,4,6,7,11. RSW's old literal flag word 0 is a mathematical nonvacuity witness, not a claim that that record is a valid physical RFLAGS image. The original callee constructors use flag word 2 and are separately checked normal witnesses.

The initial x87/SIMD/OS-enabled state must be legal for the declared processor. MXCSR bits above bit 15 are reserved and zero; its DAZ bit 6 may be set only when supported by the processor's MXCSR mask. The selected routines do not issue x87/SIMD instructions and preserve the added fields and existing SIMD state in their qualified scalar model. The old reset witnesses have x87 CW=0x37f, empty tags=0xffff, zero status/opcode/pointers/register contents and MXCSR=0x1f80, so supported DAZ is not needed for them. Physical FS/GS selectors and bases must obey the processor's legal-state/canonical-base rules; only FS base canonicality is required by the original abstract interface, because no scoped routine accesses either segment base. Additional legal initial GS/selector constraints belong to the physical mapping, not hidden implementation assumptions.

The actual Crypto and Cleanse PLT hops load canonical constant targets 0x10241840 and 0x102417d0. Generic arbitrary-target jump suppliers do not establish fault-free physical execution for noncanonical targets. The unchanged E3 exact-GOT predicate, checked canonical-GOT lemma, preserved GOT bytes and actual linked stub transitions supply the caller-specific result. Subsequent target instruction fetches are covered separately in the accepted all-successor run.

A formal proof of these model invariants and normal-overlay equality closes the concrete RF preservation mismatch for this restricted domain. It does not certify the rest of a processor implementation; architectural justification of the selected scalar/REP-RET/omitted-state clauses remains an enumerated trusted input.
