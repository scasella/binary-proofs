# C2 contract, before proof construction

The authored experimental `c2_equal_and_clear_if_equal(secret,expected,n)` compares its two initial logical byte sequences using `CRYPTO_memcmp`. It returns the full 64-bit RAX value 1 if the initial sequences are equal and 0 otherwise. Equality is evaluated against the initial memory map m, before the first caller stack write and before cleanup.

If the initial sequences are equal, the caller invokes `OPENSSL_cleanse` on exactly the secret region and that region is zero on return. If they differ, it skips cleanup and permits no destination write at any intermediate step. Final memory outside the actual caller scratch is unchanged on this branch. On the equal branch, final memory outside the secret region and scratch is unchanged. The step policy makes this branch distinction explicit using initial equality, so endpoint restoration cannot conceal forbidden destination writes.

The two logical inputs may be identical or partially overlap. Neither input may overlap caller scratch `[S-32,S)`, because PUSH/CALL write there before comparison. The secret region may not overlap the incoming return slot `[S,S+8)`, because cleanup must protect that return address. The expected region may overlap that slot when other conditions hold. There is no p/q separation premise. If cleanup changes part of expected because of overlap with secret, that is permitted: the returned comparison result still concerns the initial sequences, and only bytes outside the cleared region and scratch are preserved.

For all admissible lengths `n < 2^64`, p and q require stable, ordinary readable logical regions. The secret region also requires ordinary write permission; this is an unconditional precondition for the potential cleanup branch, and does not license writes on the unequal branch. Precise span predicates exclude accessed noncanonical addresses and arithmetic wraparound. No alignment premise is imposed on inputs. For zero length the comparison is true, the result is 1, and the cleanse call is taken, but neither supplier accesses a buffer. The input spans are empty and impose no p/q readability, writability or canonical-address premise. Stack, code and GOT requirements remain.

The compiled caller saves R12, RBP and RBX at `[S-8,S)`, `[S-16,S-8)` and `[S-24,S-16)`. Each CALL writes the same nested return slot `[S-32,S-24)`. All 32 scratch bytes require ordinary read/write permission. The incoming return slot requires read permission and is protected. Entry RSP is congruent to 8 modulo 16, downward subtraction and restored RSP do not wrap, and the incoming return address is canonical and differs from the entry PC. The completed theorem must restore RSP to S+8 through the actual RET, preserve RBX/RBP/R12/R13/R14/R15 and omitted ABI state, preserve code and GOT contents, and account for every fetch/read/write width.

The exact loaded image uses the final C2 ET_DYN artifact at fixed bias `0x22000000`, with immutable segment bytes, explicit post-initialization RW contents, explicit padding, and declared 4096-byte page permissions. Both NOW-bound PLT/GOT targets are explicit post-initialization assumptions. Their initial correctness is not an assumed functional guarantee; the proof must establish the CALL and PLT transfer and discharge the existing public supplier preconditions. There is no dynamic-loader execution, arbitrary ASLR, interposition, lazy binding, concurrency or additional processor profile claim.

E5 normal entry remains RF=TF=0, DF=0 and AC=0 with canonical FS base. The existing architectural interpretation assumptions remain: x86-64 long mode/CPL3, no delivered asynchronous events/debug interference, no hardware breakpoints, and disabled CET in the declared scope. No new semantics or trusted axiom is authorized. Physical ISA fidelity, extraction/loading and the architecture interpretation remain under the existing trust inventory.

Seven literal targets are in statements-v1.ml: the complete checked execution, extended ABI interface, normal checked execution, RF-retired checked execution, normal extended interface, actual eight-step CRYPTO handoff, and exact branch-sensitive count expression. Every successor is subject to the original checked-run policy, not a selected safe execution. The supplier call counts remain unchanged. The unequal caller adds 16 steps; the equal caller adds 20 plus the unchanged cleanse call count.

No caller trace-noninterference statement is proposed. The conditional branch intentionally depends on comparison outcome. This is a machine-code experiment, not a C-language refinement claim, deployed integration, complete secure erasure, complete library proof, or H2/H3 finding. Human review remains PENDING.
